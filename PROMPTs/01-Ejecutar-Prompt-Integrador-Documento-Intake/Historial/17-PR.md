## Resumen
Primer PR del Incremento C (lo divido en **C1 backend** + **C2 UI** por tamaño): la persistencia EF Core del dominio de equipos y el caso de uso transaccional de alta (CU-02). Sin panel todavía.

### Persistencia (EF Core + SQLite, ADR-18)
- Configuración de catálogo, inventario (`UnidadFisica` con **TPH**), vínculos temporales y verificaciones.
- `Vigencia` / `Valor<T>` como **complex types**; **índices únicos parciales** `WHERE Hasta IS NULL` ("a lo sumo uno vigente", RC-02); CHECKs (baja lógica coherente, intervalo, I-21); migración `EsquemaEquipos`.

### Dominio
- Entidad `Verificacion` (cuatro supuestos), enum `Modalidad`, `EvaluadorModalidad` (degradación a `SoloAlerta` mientras no estén los cuatro verificados, RN-01/RN-02).

### Aplicación
- `ServicioAltaEquipos` (CU-02): crea catálogo+inventario, abre `MontajeBateria`/`CoberturaHost` con fin abierto (validando no solapamiento), siembra las 4 verificaciones en `NuncaVerificado`, fuerza modalidad efectiva `SoloAlerta`. **Transaccional** (un `SaveChanges`).

### Decisión de diseño (a tener presente)
- **Clave por `Codigo`**: el dominio (Incremento A, ya mergeado) se referencia por código string, no por `Id` int. Mapeo por código → **desvío documentado** del modelo lógico que preveía `Id INTEGER`. Se agregó un **constructor privado de materialización** para EF que **no** mete dependencia de framework en el dominio (sigue framework-free).

### Verificación
- 9 pruebas nuevas (dominio + integración contra la base real): alta completa siembra 4 en solo aviso; RN-13 no persiste nada; el índice único parcial rechaza un segundo montaje vigente; estado de puesta en marcha degradado. **Suite 91/91 + 3 omitidas**, build 0/0, `dotnet format` limpio.
Dos cosas para tu ojo antes de mergear:

La clave por Codigo (en vez de Id int del modelo lógico) — lo impuso el dominio ya mergeado; si preferís que reabramos el dominio para usar Id, decímelo, pero el mapeo por código es más limpio dado lo que hay.
El constructor privado de materialización en 3 entidades (ModeloDispositivo, MontajeBateria, CoberturaHost) — necesario porque EF no puede pasar un value object (Vigencia/Valor) como parámetro de constructor. No agrega using de EF al dominio.
Cuando mergees y borres la rama, avisame con un "mergeado" y sigo con C2 (panel MudBlazor del alta: wizard de descubrimiento→declarar→confirmar, + banner «0 de 4 supuestos verificados» en el panel principal), que es donde volvés a validar en el navegador.
