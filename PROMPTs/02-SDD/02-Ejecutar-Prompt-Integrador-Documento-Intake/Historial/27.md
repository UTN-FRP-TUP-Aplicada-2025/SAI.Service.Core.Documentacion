Qué cierra
El lazo completo detección → decisión → ejecución → confirmación → registro. El monitoreo ya derivaba el disparo (DisparoApagado, BT-20); ahora ServicioMonitoreo.cs invoca a ServicioApagadoOrdenado.cs, que:

deriva la modalidad efectiva con el bloqueo por verificación (RN-02, ADR-10);
solo si habilita acción, ordena el apagado con retorno y lo confirma por efecto observado (ADR-11) — ejecutada solo si el equipo admitió la orden, nunca por ausencia de excepción;
registra toda decisión como una Accion append-only, con tiempo reservado ≤ 540 s (techo duro RN-04).
Nueva modalidad CicloForzado (ADR-09): el corte no se cancela aunque vuelva la red; nunca shutdown.stop.

Write path NUT real (US-14)
Sesión autenticada USERNAME/PASSWORD/LOGIN + SET VAR (retardos) + INSTCMD shutdown.return (y test.battery.start.quick), en ClienteNut.cs/AdaptadorConexionNut.cs. Credenciales por Sai:Nut:Usuario/Password; sin ellas el efecto no se confirma.

⚠️ El apagado real nunca se dispara contra un host en desarrollo. Se valida con el simulado (que ahora puede reportarse en batería) y el cliente NUT falso. Además, el SAI de dev sólo expone credenciales RO, así que el write path real ni siquiera es ejecutable ahí.
