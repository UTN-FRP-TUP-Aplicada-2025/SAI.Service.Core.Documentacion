Pero tu log destapó un problema real ⚠️
Mirá estas líneas del arranque de upsmon (16:55:26):


UPS: sai@localhost (primary) (power value 1)
Primary managerial privileges unavailable on UPS [sai@localhost]
Response: [ERR ACCESS-DENIED]
Traducción: upsmon arranca como primary (master) —correcto, porque este host tiene el SAI por USB— pero cuando le pide a upsd los privilegios de primary, se los niegan. ¿Por qué? Porque en upsd.users, saimon está como upsmon slave, no master. Hay un desajuste de rol:

upsmon.conf → MONITOR ... master
upsd.users → saimon ... upsmon slave ← acá está el problema
Qué implica: el monitoreo anda (por eso viste "on battery"), pero en un apagado real, upsmon no puede ejercer su rol de primary — no puede setear el flag FSD ni dar la orden final de corte al SAI (killpower) cuando el SO termina de apagarse. O sea, el apagado limpio quedaría a medias. Esto no lo hubieras visto con solo mirar "on battery / on line" — la verificación lo destapó.

El arreglo
En /etc/nut/upsd.users, cambiá el rol de saimon de slave a master:


[saimon]
    password = saimon
    upsmon master          # ← era 'slave'
    actions = SET
    instcmds = shutdown.return
    instcmds = test.battery.start.quick
upsmon master le da los privilegios que faltan (incluido FSD). Después:


sudo systemctl reload nut-server      # que upsd tome el nuevo permiso
sudo systemctl restart nut-monitor    # que upsmon reintente el login primary
sudo journalctl -u nut-monitor -e | tail -15
En ese log, tras el restart, ya no debería aparecer ERR ACCESS-DENIED ni "Primary managerial privileges unavailable". Si desaparecen, quedó bien.
